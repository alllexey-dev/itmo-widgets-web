# ITMO.Widgets — веб-приложение

Веб-версия ITMO.Widgets на `https://<домен>/app/` (сначала
`https://dev.widgets.alllexey.dev/app/`). Сейчас в ней главная и админка для
модераторов и администратора; разделы для студентов появятся позже. Вход —
только через телефон: сайт показывает QR и код, приложение подтверждает вход,
бэкенд ставит httpOnly-cookie `iw_session`.

Стек: Vite, React 18, TypeScript (strict), React Router 7 (`basename="/app"`),
TanStack Query v5, CSS Modules, recharts (только на дашборде), Vitest + Testing
Library + MSW.

Подробнее: [архитектура](docs/architecture.md), [дизайн](docs/design.md).
Контракты бэкенда — `docs/contracts/web.md` и `docs/contracts/admin.md` в
репозитории `itmo-widgets-backend`.

## Разделы

### Главная — `/`, всем

Профиль: имя, ИСУ, группы, роль. Модератору — число открытых заявок со ссылкой
в очередь, остальным — карточка «Веб-версия в разработке».

### Модерация — `/admin/moderation`, модератору

- Заявки на ссылки предметов и на отзывы о преподавателях в одной очереди.
- Вкладки «Открытые» и «Решённые», фильтр по причине: «Проверка», «Жалобы»,
  «Голоса».
- Заявка на ссылку: изменения между версиями ссылки, автор, жалобы, история
  решений.
- Заявка на отзыв: преподаватель (имя из My ITMO и ИСУ), предмет, текст,
  «Анонимно» или «С именем», проверка по ИСУ («Вёл у автора», «Проверяется»,
  «Не подтверждён»), рейтинг; для правки — разница с одобренной версией
  (предмет таблицей, текст по словам). Автор виден модератору и у анонимного
  отзыва.
- Действия: «Одобрить», «Отклонить», «Скрыть», «Вернуть», «Отклонить жалобы»,
  «Ограничить», «Скрыть всё у автора». Для отзывов — свои готовые причины
  отклонения, ограничение по умолчанию «Отзывы» и «Скрыть все отзывы автора?».
- Причина обязательна при отклонении и ограничении: её видит автор в
  приложении, без неё он увидел бы технический текст бэкенда.
- На широком экране список и заявка рядом, первая заявка открывается сама; на
  узком — сначала список.

### Ограничения — `/admin/restrictions`, модератору

Ограничения авторов после решений модерации: поиск по ИСУ, только активные или
все, снятие ограничения.

### Дашборд — `/admin/dashboard`, администратору

Итоги (пользователи, активные устройства, входы на сайт, дружбы, очереди
спорта, открытые заявки), графики новых пользователей, активных устройств и
новых ссылок за 30 дней, ссылки по статусам, таблица по дням.

### Пользователи — `/admin/users`, администратору

Поиск по ИСУ, имени или группе. Страница `/admin/users/:isu`: последняя
активность, регистрация, друзья, ссылки, устройства, все группы и переключатель
«Модератор» с подтверждением.

### Спорт — `/admin/sport`, администратору

Состояние автозаписи: последний успешный запуск, запуски и средняя длительность
за 7 дней, сколько записей ждут автозаписи и свободного места, ошибки за 7 дней,
список запусков.

### Система — `/admin/system`, администратору

- Версия приложения: «Последняя», «Минимальная», «Заметка к обновлению».
- Модерация ссылок: премодерация, «Жалоб до проверки», «Рейтинг для проверки»,
  «Ссылок в сутки», «Жалоб в сутки». Выключение премодерации — с
  подтверждением.
- Модерация отзывов: те же пороги, «Отзывов в сутки»; премодерация отзывов
  всегда включена, переключателя нет.
- Учётные данные: refresh-, access- и ID-токен My ITMO, cookie ИСУ
  `KEYCLOAK_IDENTITY` и ключ Gemini для ИИ-сводок («Gemini · API-ключ»,
  `GEMINI_API_KEY`, вид `API_KEY`). Для каждого — статус, последняя ошибка,
  срок и «Скоро» перед истечением, когда использовано, обновлено у сервиса и
  кем изменено. Сами значения не показываются. «Заменить» есть у
  refresh-токена, cookie и ключа Gemini (подсказка в диалоге — «Ключ из Google
  AI Studio»): новое значение вводится в скрытое поле и уходит только в запрос;
  пока свежее значение не проверено, таблица обновляется сама. Подробнее —
  `docs/ops/service-credentials.md` в `itmo-widgets-backend`.

### Отзывы — `/admin/reviews`, администратору

Копия отзывов о преподавателях из проекта Reviews: бэкенд забирает их раз в
сутки в 05:00 по Москве. Карточка «Синхронизация»: состояние («Идёт
синхронизация», «Обновлено», «Без изменений», «Ошибка» с технической строкой,
«Выключена на сервере»), когда проверяли и когда были изменения, сколько
отзывов, удалённых и преподавателей, итог последнего запуска с изменениями.
Кнопка «Синхронизировать» запускает синхронизацию сразу; пока она идёт,
карточка обновляется сама. Подробнее — `docs/ops/reviews-sync.md` в
`itmo-widgets-backend`.

Карточка «Проверка по ИСУ»: сколько своих отзывов «На проверке»,
«Подтверждено» и «Не подтверждено» — вёл ли преподаватель у автора. Подробнее —
`docs/ops/isu-verification.md` в `itmo-widgets-backend`.

Карточка «ИИ-сводки» (в подзаголовке — модель Gemini): состояние («Выключены
на сервере», «Идёт пересчёт», «Ещё не запускался» или итог последнего запуска:
«Готово», «Лимит исчерпан», «Ограничение Google», «Нет ключа», «Ключ не
принят», «Ошибка» с технической строкой), когда и кем запущен пересчёт («по
расписанию» или «администратором»), сколько сводок «Готовы», «В очереди»,
«Ошибки» и «Скрыты», «Запросов сегодня» — `N из M` дневного бюджета с датой
дня квоты Google (по тихоокеанскому времени), итог последнего запуска:
построено, отклонено, запросов. Если ключ Gemini не задан или не принят,
карточка предупреждает об этом со ссылкой «Учётные данные». Бэкенд сам
пересчитывает сводки раз в сутки в 05:30 по Москве. «Пересчитать всё» после
подтверждения запускает пересчёт сразу — только для преподавателей с
изменившимися отзывами и в пределах оставшихся запросов; без ключа и при
сводках, выключенных на сервере, кнопка недоступна. Пока идёт пересчёт,
карточка обновляется сама, а после него — и таблица.

Таблица «Сводки преподавателей»: вкладки «Все», «Готовы», «В очереди»,
«Ошибки», «Скрыты» и страницы; колонки «Преподаватель» (имя и ИСУ или только
ИСУ), «Статус», «Отзывов» (сейчас), «Тон», «Построена» и «Ошибка» с кодом
отказа. Строка открывает сводку: описание, плюсы, минусы, теги (неизвестный
код — как есть), пять шкал словами с причинами, тон и уверенность, по скольким
отзывам и когда построена, кто и когда скрыл, последняя ошибка с числом
попыток. Тексты модели выводятся только как текст. «Скрыть» убирает сводку из
приложения, «Показать» возвращает. «Пересчитать» ставит преподавателя первым в
очередь и запускает пересчёт, если он не идёт; у скрытой сводки, при меньше чем
трёх отзывах и при выключенных сводках кнопка недоступна. Подробнее —
`docs/ops/ai-summaries.md` в `itmo-widgets-backend`.

### Журнал — `/admin/audit`, администратору

Кто и когда менял роли, правила модерации и версию приложения, запускал
синхронизацию отзывов и пересчёт ИИ-сводок, скрывал, показывал и пересчитывал
сводку преподавателя и заменял учётные данные (без значений).

Действия ИИ-сводок: «Пересчёт ИИ-сводок» (`AI_SUMMARIES_RUN_STARTED`, цель
«ИИ-сводки», `ai-summaries`; только запуск администратором), «Сводка скрыта»
(`AI_SUMMARY_HIDDEN`), «Сводка показана» (`AI_SUMMARY_SHOWN`) и «Пересчёт
сводки» (`AI_SUMMARY_REGENERATION_REQUESTED`) с целью «Преподаватель · ИСУ N»
(`teacher:N`). Замена ключа Gemini — цель «Gemini · API-ключ»
(`credential:GEMINI_API_KEY`).

Фильтры, страница и открытая заявка хранятся в адресе (`?status=`, `?reason=`,
`?case=`, `?page=`, `?q=`, `?isu=`), так что ссылкой на заявку или выборку можно
поделиться.

## Роли

- **Пользователь** — любой, кто вошёл: главная.
- **Модератор** (`MODERATOR`) — модерация и ограничения. Назначает и снимает
  администратор на странице пользователя.
- **Администратор** (`ADMIN`) — всё, что может модератор, плюс дашборд,
  пользователи, спорт, система, отзывы и журнал. Выдаётся только через SQL на сервере.

Навигация показывает только доступные разделы. Прямой переход в чужой раздел
показывает «Нет доступа» и не делает запросов. Права проверяет бэкенд,
интерфейс только прячет лишнее.

## Горячие клавиши

В очереди модерации, когда фокус не в поле ввода и не открыт диалог:

| Клавиша | Действие                     |
| ------- | ---------------------------- |
| `J`     | Следующая заявка             |
| `K`     | Предыдущая заявка            |
| `A`     | Одобрить открытую заявку     |
| `R`     | Отклонить (открывает диалог) |

Клавиши читаются по `KeyboardEvent.code`, поэтому работают и в русской
раскладке. С `Ctrl`, `Cmd` и `Alt` не срабатывают.

## Как работает вход

1. Страница `/app/login` создаёт код (`POST /api/web/auth/challenges`):
   8 символов без похожих `0 O 1 I L`, живёт 2 минуты. QR содержит
   `https://<домен>/app/login?code=<код>`.
2. В приложении: Профиль → «Вход на сайт» → QR или код → «Войти». Строка есть
   только при включённом «Подключение к ITMO.Widgets».
3. Страница спрашивает статус раз в 2 секунды с секретом из шага 1, пока вкладка
   видна; при возврате на вкладку — сразу. Подтверждённый вход приходит вместе
   с cookie сессии, и страница открывает главную.
4. Устаревший код заменяется сам, не больше 5 раз подряд; потом страница
   показывает «Код устарел» и ждёт «Показать новый код». Ответ 429 — «Слишком
   много попыток, подождите пару минут».

QR, открытый камерой телефона, ведёт на `/app/login?code=…` с подсказкой ввести
этот код в приложении.

Сессия заканчивается через 2 часа без запросов или через 12 часов после входа.
«Выйти» — в меню аккаунта; там же тема: «Как в системе», «Светлая», «Тёмная».
Подтвердить вход можно только из приложения: веб-сессия не может подтвердить
другой браузер.

## Запуск

Для разработки и CI используется Node.js 22.23.3 (`.nvmrc`), как в сборочном
образе Docker. Оба базовых образа закреплены по версии и digest: Node.js
22.23.3-alpine и nginx 1.31.6-alpine.

```bash
cd web
npm ci
npm run dev
```

Приложение открывается на `http://localhost:5173/app/`. Запросы `/api` уходят
на `https://dev.widgets.alllexey.dev` через прокси Vite.

Ограничения локального запуска:

- Коды создаёт dev-бэкенд, поэтому подтверждать их нужно debug-сборкой
  приложения: она ходит в dev-бэкенд, release — в прод.
- QR с `http://localhost` приложение не примет (оно берёт только ссылки
  `https://…/app/login?code=`), код нужно ввести вручную.
- Cookie сессии выдаётся с `Secure`, `SameSite=Strict` и `Path=/api`; не все
  браузеры сохраняют такую cookie на `http://localhost`. Вход целиком
  проверяйте на `https://dev.widgets.alllexey.dev/app/`.
- Для разделов админки нужна роль на dev-бэкенде.

## Команды

| Команда             | Что делает                        |
| ------------------- | --------------------------------- |
| `npm run dev`       | Dev-сервер с прокси `/api`        |
| `npm run build`     | Проверка типов и сборка в `dist/` |
| `npm run preview`   | Раздача собранного `dist/`        |
| `npm run lint`      | ESLint                            |
| `npm run typecheck` | `tsc --noEmit`                    |
| `npm test`          | Vitest (jsdom, MSW)               |
| `npm run format`    | Prettier                          |

Перед коммитом: `npm run lint && npm run typecheck && npm test && npm run build`.

## Структура

- `src/app/` — корень приложения, маршруты, оболочка (боковая навигация,
  верхняя панель, меню аккаунта), навигация по ролям, `RequireAccess`,
  страницы «Нет доступа» и «Не найдено».
- `src/api/client.ts` — `fetch` с `credentials: 'same-origin'`, заголовок
  `X-Web-Request: 1` для изменяющих запросов, разворачивание `ApiResponse`,
  `ApiError` с кодом ошибки бэкенда; 401 на любом запросе и 403 на
  `/api/web/auth/me` ведут на `/app/login`. `src/api/errors.ts` — русские
  тексты по кодам ошибок, `src/api/admin.ts` — общие типы админки.
- `src/features/<раздел>/` — `auth`, `home`, `moderation` (вместе с
  ограничениями), `users`, `dashboard`, `system` (спорт и система), `reviews`,
  `audit`; тесты рядом с кодом.
- `src/ui/` — дизайн-система: токены (`tokens.css`), компоненты, тема.
- `src/test/` — настройка Vitest, MSW-сервер, данные и хелперы рендера.

## Дизайн

Токены повторяют лендинг (`site/style.css`) и роли Material 3 приложения:
`--primary #3a5488`, плоские поверхности, радиус карточек 20 px, кнопки-пилюли
48 px, сетка 4 px, шрифт Roboto со системными запасными. Тёмная тема — по
`prefers-color-scheme` или вручную в меню аккаунта (хранится в `localStorage`,
ключ `iw-theme`). Иконки — Material Symbols Rounded через Google Fonts.
Статус никогда не передаётся только цветом. Подробности —
[docs/design.md](docs/design.md).
